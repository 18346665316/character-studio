# Studio 操作审查 · 2026-11-02

本轮只审查，不修改界面和生产逻辑。目标是判断操作是否必要、位置是否合理，以及是否能完成用户意图。

## 范围与证据

核对素材库、制作入口、任务中心、人物模型/绑定/动作/游戏素材/辅助工具，以及地面、道路、水面、地表过渡、水岸、物件和围栏的制作与详情页面。检查页面结构、表单事件、提交参数及后台处理；在本机 Chrome 中复现关键问题。

涉及提交的浏览器检查拦截了 HTTP POST，以模拟错误并检查参数，没有创建生产任务或调用生图服务。没有重新验证 Mixamo 下载、AI 生图效果和 Godot 导出后运行。

复现数据：`.local/debug/ui-audit/operations.json`。该文件及截图仅在本机，不提交版本库。

## 结论

一级入口划分可以保留，但内部尚未充分区分“制作新素材”“调整当前素材”“查看历史任务”三种上下文。四个固定页签把一些不同含义的操作放在了一起。下一轮应先修正行为与含义，再减少重复操作，不需要继续增加一级导航。

下面将直接影响正确使用的问题标为“先修”，操作组织问题标为“重整”，可选复杂度标为“下放”。建议与已复现事实分别说明。

## 先修：操作结果与预期不一致

### 1. 进入新建页面就展示另一份历史素材

- 复现：打开“制作素材 → 独立物件”，左侧是新建表单，右侧已经显示“木箱 · 程序几何验证样本 · 非AI素材”，导出目标是已有木箱。
- 原因：`props.js` 的 `refresh()` 默认取首个套件；其他制作页也会自动选择已有成果。
- 影响：输入描述和预览/下载不属于同一个任务，用户难以判断是否已经生成、参数是否已生效。
- 建议：新建默认显示空预览及本次任务；历史素材通过明确入口打开。若要展示示例，必须说明其与当前输入无关。

### 2. 完成任务没有可靠地打开对应成果

- 地表复现：任务记录中点击“查看成果”，选中了目标套件，但当前页签仍是“版本与记录”，“预览”继续隐藏。
- 物件复现：打开已完成的灌木任务 `20261101-221737-b973aa63`，记录只有原图/日志入口；详情当前选择却是木箱 `20261102-103124-996ccfb6`，不是此任务的成果。
- 围栏代码同样缺少已完成任务到成果的入口，本机没有已完成 AI 围栏任务，未做对应成功态实机复现。
- 建议：任务到成果建立明确链接，显示成果名称；点击直接打开该成果预览。无关联成果的任务说明原因，不能默认借用其他成果。
- 位置：`terrain.js` 的任务按钮处理、`props.js` 的 `jobs()`、`components.js` 的 `refresh()`、`hub.js` 的 `taskCard()`。

### 3. 重试请求的即时错误不可见

- 复现：从任务中心打开失败物件任务，点击继续，以拦截 POST 的方式返回错误。`#prop-status` 收到了错误，但位于被隐藏的制作表单，用户看不到。
- 影响：用户无法知道请求被拒绝，可能重复点击。原任务记录中的历史错误不能代替此次请求的反馈。
- 建议：任务操作的即时反馈放在任务记录旁；制作、调整各自拥有本操作区可见的状态。
- 位置：`asset-workspace.js` 的 task 布局、`props.js` 的 `status()` 与重试处理。地表和围栏也使用制作表单中的状态元素，需一并核对。

### 4. 地表调整名称不会生效

- 复现：修改“套件名称”为“审查填写的新名称”，点击另存；请求仍为“原名称 · 重新制作”，并未采用填写的名称。
- 原因：`terrain.js` 的 `reuse-materials.onclick` 使用 `source.title`，而调整页暴露了可编辑的 `#kit-title`。
- 建议：保留命名则实际提交；若不允许命名，应显示只读名称。不要提供无效输入。

### 5. “版本与记录”可以切换到无关素材，并静默丢掉修改

- 复现：修改木箱锚点 X 为 7.5，进入记录选择“灌木”，再切回木箱，锚点变回 128，没有提示，草稿也没保留。
- 原因：这里使用全类别历史列表，而非当前素材的派生版本；`props.js` 的 `show(kit, true)` 直接覆盖表单。
- 影响：操作名暗示版本管理，实际行为类似第二个素材库，并会丢失未保存数据。
- 建议：版本只列当前素材的相关版本。其他素材回素材库切换；有修改时保留草稿，或在离开前给出明确选择。

## 重整：操作是否合理、是否需要

### 6. 围栏“调整”实际是新建另一套围栏

- 现状：页签中包含碰撞范围展示和完整制作表单，标题为“制作另一套围栏”，来源默认 AI；没有修改当前围栏的几何/木纹/碰撞参数。
- 判断：查看碰撞建议是必要的；将付费新建包装成当前素材的调整不合理。
- 建议：碰撞展示归入预览；“制作类似围栏”作为独立的新建操作，有真实复用能力时再提供“基于当前版本制作”。目前不需要为围栏硬凑调整页。

### 7. 物件调整缺少视觉反馈

- 复现：修改锚点、碰撞宽度后，`anchor_collision.png` 仍为保存前的静态图片；页面也没有未保存提示。
- 判断：锚点调整是必要能力；手工填写图像坐标不宜成为主要操作。
- 建议：图上点选/拖动锚点，叠加实时占地轮廓；数值用于精调。明确显示未保存，保存后打开新版本并允许对照。

### 8. 人物的手动动作流程与整套生产并列，重复劳动边界不清

- 现状：编号主线把“动作”放在“游戏素材”之前。动作页提供添加、姿态检查、确认、逐动作/批量图集生成；游戏素材页又可填写动作清单，一次下载缺失项并渲染整套。
- 依据：`workspace.js` 的 `renderActionLibrary()`、`renderAnimation()`、`renderActionSet()`；`production.py` 的验证与运行过程只要求当前绑定就绪，不要求先逐动作确认。
- 判断：两条路径都有用途，但无需让常规用户先逐个导入、确认、生成，再去整套生成。
- 建议：主路线为“模型确认 → 绑定 → 配置动作清单 → 整套生成 → 逐动作检查成果 → 导出”。原动作来源、朝向校准、单动作重做保留为按需工具。朝向或变形存在问题时仍应能回到原动作检查。

### 9. 人物验收操作放得太深

- 现状：整套成果主页面可以预览及导出；保存每个动作人工检查状态，要进入“高级管理 → 管理采用版本与单动作验收”。
- 判断：版本来源替换是高级操作，但检查姿态、风格、循环/结束效果是常规操作，不应该一起隐藏。
- 建议：成果主页面直接记录单动作检查状态；技术参数与来源替换继续下放。区分“生成完成”“结构通过”“人工检查”。是否必须验收才允许导出，是产品规则，不应由本次审查擅自增加硬门槛。

### 10. 水面到水岸的后续操作位置不合理

- 复现：已选水面的“制作水岸”入口在预览页不可见，进入“调整”才出现。素材库卡片另有该快捷入口。
- 判断：这是基于当前素材继续制作另一类产物，操作本身有必要；不属于修改水面。
- 建议：放在水面预览后的“后续制作”区域，直接带入当前水面。保留先独立确认水面、再制作水岸的两步结构。

### 11. 新建人物的入口承诺与弹窗不一致

- 现状：“制作素材”写明支持原画或 GLB，进入后立即打开强制选择原画的弹窗。已有 GLB 的用户必须关闭它，再找背后的“导入 GLB”。
- 判断：两种输入都有必要；这一步不应该默认替用户选定原画。
- 建议：新建人物先提供“从原画制作 / 导入已有模型”两个来源选项。

### 12. 导出不总需要独占页签

- 现状：物件及地表的导出基本只有单个 ZIP 与说明，用户必须离开预览才能下载。
- 判断：明确的导出入口必需；单个固定格式下载不必形成一个完整阶段。
- 建议：固定格式在预览页提供主要下载按钮，接入说明折叠；人物有动作集、采样、版本等真实交付选择，可以保留交付工作区。统一的是动作含义和位置，不必统一页签数量。

### 13. 来源/投影规格的兼容性提示不足

- 现状：过渡制作的来源列表包含等距材质包，但后台读取的是包内保留的方形正俯视纹理并制作方形过渡，未输出等距过渡。
- 判断：复用底层纹理有技术意义，但标签会使用户误以为获得等距过渡；这不是直接证明后台算法错误。
- 建议：来源列表明确标注使用哪份纹理及输出投影。当前未支持的等距过渡不能通过选择来源被暗示为已支持；视产品定位决定过滤或明确转换。

## 下放：不需要每次都做的选择

| 操作/参数 | 判断 | 建议位置 |
| --- | --- | --- |
| AI 生成 / 导入 | 必要的不同来源 | 新建起点 |
| 人物原画 / GLB | 必要的不同来源 | 人物新建起点 |
| 风格参考图 | 可选，但有直接意义 | 新建描述旁 |
| 投影视角 | 影响能否配套使用 | 制作规格，清楚显示当前值 |
| 尺寸 | 必要，但不应反复猜测 | 常用规格与高级自定义 |
| 物件碰撞建议用途 | 接入相关，可选 | 调整/接入设置；新建不必强迫决定 |
| 过渡格子尺寸下拉 | 当前由来源尺寸唯一决定，无真正选择 | 显示只读尺寸与来源不匹配提示 |
| 道路宽度 | 直接影响产物 | 道路制作规格；其他类型不出现 |
| 基础连接旧版处理 | 对照/兼容用途 | 高级处理，不与推荐方案同等强调 |
| 程序示例 | 开发验证有用，非正常生产 | 示例与验证入口 |
| 渲染器、超采样 | 有专业用途 | 高级设置，默认值即可 |
| 颜色、精简 | 直接影响游戏素材 | 成果调整；可共用整套方案 |
| 模型减面实验 | 非所有人物必需，采用会影响后续绑定 | 模型高级工具，不持续占据已确认模型的主操作区 |
| 朝向校准 | 有问题时必要 | 原动作检查/修正工具 |
| 装备与编排 | 有独立用途 | 辅助工具，按需进入 |
| 请求日志、指纹、内部编号 | 排障/追溯需要 | 记录详情，主界面优先名称与结果 |
| 保存、下载、查看任务成果 | 高频且必要 | 就近明确呈现，不借助其他页签猜测 |

## 建议的最短操作链

- 新物件：选择来源 → 描述或导入 → 制作 → 检查外观 → 必要时调整锚点 → 下载。
- 地面/道路：选择产物与来源 → 设置规格 → 制作 → 检查铺设 → 下载。
- 过渡：选择两种兼容来源 → 查看自动确定的规格 → 制作 → 检查连接 → 下载。
- 水岸：已有水面 → 制作水岸 → 选择兼容陆地 → 制作 → 检查 → 下载。
- 围栏：选择木纹来源 → 制作 → 查看组合/占地 → 下载；当前无编辑能力就不显示“调整当前围栏”。
- 人物：模型准备与确认 → 骨骼绑定 → 整套动作方案 → 生产 → 检查成果 → 导出。单动作与专业工具按需进入。
- 失败任务：查看此次失败原因 → 继续或修正 → 得到本次明确反馈 → 完成后打开关联成果。

## 修改顺序

1. 修正“任务 → 成果”、隐藏反馈、无效名称输入和未保存修改丢失，避免操作结果错误。
2. 分开新建与已有成果上下文，移除不具备实际编辑能力的调整入口。
3. 整理人物手动/自动流程，将成果验收移到常规主界面。
4. 再下放低频参数，简化导出和来源选择。
5. 素材与版本关系单独设计；不要继续把全类历史列表称为当前素材的版本历史。

本轮不建议加功能数量，也不建议立即重写全部界面。先消除已复现的行为问题，再按最短操作链逐页收敛。


## 本轮落实与验证

已落实以上修改顺序：新建与成果上下文分开；任务准确关联成果并显示即时反馈；地面重制采用实际输入名称；物件锚点与占地实时预览，草稿在相关版本切换和刷新后保留；仅显示明确关联的版本。下载合入预览，围栏移除无实际编辑能力的调整页，水面预览直接进入水岸制作，过渡规格由兼容来源确定。

人物主流程收敛为模型、骨骼绑定、动作与交付；整套生产与人工检查进入主界面，单动作和专业工具按需进入。检查状态保存保留采用来源与播放设置，并通过修订号防止覆盖其他页面的更新。

验证通过：23 项面板测试、5 项动作集测试、6 项浏览器操作回归；另以真实项目只读数据验证六类成果入口、下载、人物来源选择、人工检查保存往返及并发冲突处理。浏览器制作与保存请求使用拦截响应，未启动付费生产或修改已有角色检查状态。

限制：缺少明确来源记录的历史素材不会自动推断版本关系；人工检查仍由使用者完成，自动结构验证不代表美术验收。


## 第二轮：选择的来源与实际作用

首轮主要处理入口组织；本轮补查每项输入是否被当前操作消费，避免只换位置而保留含义不清的表单。

| 流程 | 输入的实际作用 | 本轮处理 |
| --- | --- | --- |
| 地面/水面 AI 生成 | 描述决定纹理内容，参考图约束画风，随后制作地格 | 仅生成时显示并提交 AI 输入；地面默认描述改为示例提示，避免替用户指定草地风格 |
| 地面/水面导入 | 原图进入平铺与变化块处理，不执行风格迁移 | 隐藏描述与参考图，提交不携带生成参数；后端不再强制描述 |
| 普通材质分类 | generic/grass/sand/stone 是固定枚举，当前不对应不同纹理处理 | 移出制作表单，新普通地面使用 generic；保留历史记录，水面身份由水面入口确定 |
| 地格形状 | 程序把平面纹理输出为方形或菱形 | 改为“输出地格形状”，移至输出设置；道路只支持正俯视，无需用户选择 |
| 已有地面调整 | 复用原材质，仅改变名称、地格尺寸、道路宽度、处理方案及允许的地格形状 | 不要求隐藏的 AI 输入或上传；按回车与另存按钮使用同一复用流程 |
| 物件生成/导入 | 生成指定视角；导入只能声明已有视角，不能转换图片 | 分别标注“生成图片的视角”和“原图片的视角”；导入不提交残留生成描述；说明内置物件预设的用途 |
| 围栏生成/导入 | AI 只生成木纹，构件款式由程序固定；导入只消费木纹图 | 确认条件输入与请求一致；程序示例移至验证工具 |
| 过渡/水岸 | 选择已有兼容来源，输出尺寸从来源确定 | 不自动采用历史来源；显示素材名称与尺寸，说明底层/覆盖关系与缺少来源时的下一步 |
| 人物 | 原画重建与 GLB 导入使用独立表单，整套生产消费明确动作清单和规格 | 保留已拆分的来源流程；本轮未改动人物参数与生产规则 |

验证：81 项相关测试通过（包含12项浏览器操作回归），覆盖导入无 AI 调用、请求参数、必需图片校验、模式切换保留生成草稿、调整表单回车复用、明确来源选择及现有导出规格。浏览器制作请求全部拦截，未提交真实生产。
