# 陈伯待机脚滑分析

分析对象：character-50e87c3235，breathing_idle；原始动作批次 20261103-141409-b9c0fd0e，原始渲染 20261103-141423-231492f5，当前采用图集 20261103-141521-e8c354b2。仅运行隔离诊断，没有修改生产 FBX、交付图集或场景。

## 结论

脚滑主要由 Godot 导入时默认动画优化造成：髋部位置轨道被简化为一个固定关键帧，腿部旋转仍然保留，破坏了原动画中重心移动与腿部姿态的抵消关系。原始动作在 Blender 中双脚基本固定，骨骼绑定和动作源文件没有出现同量级脚滑。

当前渲染器测得参考身高为 0.0170000009 个单位，96px 对应约 5647px/单位。Godot 默认 optimizer/max_precision_error=3，对应绝对精度 0.001 单位，约 5.65px。这个精度没有按模型尺度或目标像素密度调整，足以损坏本动作的细微位移。把人物最终在场景里放大或缩小不会恢复丢失的关键帧。

## 对照实验

使用同一份 FBX、Godot 4.6.2，同一时间采样，在隔离项目中只修改导入优化设置。每只脚的位置是脚骨原点的世界坐标，屏幕水平位移按实际 45° 视角及 96px 参考身高投影。不是鞋底像素边界或接触点的精确测量。

| 导入方式 | 髋部位置关键帧数 | 左脚水平摆幅 | 右脚水平摆幅 |
| --- | ---: | ---: | ---: |
| 现有默认设置 | 1 | 7.08px | 7.23px |
| 关闭动画优化 | 299 | 0.23px | 0.05px |
| 开启优化，精度改为 6 | 242 | 0.24px | 0.07px |

Blender 独立读取原 FBX 也保留髋部运动，脚骨位移与关闭优化的 Godot 结果一致。仅关闭 animation/remove_immutable_tracks 没有效果，髋部轨道依然只有一个关键帧，因此不能把这个选项当作修复。

Godot 4.6 引擎源码证据：
- editor/import/3d/resource_importer_scene.cpp：AnimationPlayer 默认 optimizer/enabled=true、max_precision_error=3。
- scene/resources/animation.cpp：Animation::optimize 将精度转换为 pow(0.1, p_precision)，并传给位置与旋转轨道优化。

Studio 当前入口在 pipeline/studio_core.py：把 FBX 复制进临时 Godot 项目，执行 --editor --import，没有覆盖这些默认优化参数。问题在渲染采样之前已产生；pipeline/godot/baker.gd 随后忠实渲染了已受损的导入动作。

## 排除的后续环节

- 原始 298 帧渲染图集已经出现脚滑。
- 调色前后 alpha 全部一致，没有几何位置变化。
- 最终游戏 56 帧逐帧等于原图集对应 source_frame_indices 的帧，精简只改变采样与帧停留时间，没有逐帧居中或重定位；较低帧率可能让滑动更显眼，但没有创造位移。
- 原始与游戏图集锚点都是 [60,108]，相机在整段动作内固定。
- 人物包按固定锚点播放，村庄中的 elder 节点没有移动，idle 没有被交替重启。
- 当前非整数显示缩放可能带来额外的栅格采样观感，但不是上述骨骼轨道丢失的原因。

## 后续修复建议

生产流程先对所有用于渲染的动作关闭 Godot 导入动画优化，以原始采样保真作为基线；以后如需优化，应将允许误差绑定到目标像素密度，并增加髋部轨道保真和站立脚部接触误差回归。统一覆盖渲染、动作检查、预览等共享 FBX 导入入口，避免预览与交付不一致。

随后从现有 FBX 重新渲染、调色、精简、验收并发布新版本，重新采用人物动作集后更新场景引用。保留旧包。不要通过逐帧移动整个精灵、冻结第一帧或删除髋部位移掩盖问题；这些方法会破坏正常身体重心变化，而且对行走和跳跃语义不成立。

## 通用修复（2026-11-03）

Studio 新建的模型处理项目现在统一调用 `animation_import.prepare`，安装导入前插件。插件遍历导入场景中所有 AnimationPlayer，使用实际 import_id（或实际节点路径）关闭动画优化与有损压缩，不依赖角色名、骨骼名、动作名或模型大小。覆盖 FBX、GLB/GLTF 等 Godot 场景导入格式。烘焙、素材检查、人物检查台、运动采样、采样对照、3D 试验场及静态模型预览共用这一策略。朝向估计使用这些项目中已导入的同一份动作。

这是渲染源数据的保真策略；不会固定脚部、删除髋部运动、抵消跳跃或按帧重设锚点。代价是临时导入资源会保留更多关键帧。最终 2D 图集仍走已有像素处理和时序压缩流程。新烘焙 job.json 与交付 manifest.source 记录 `animation_import_policy.version = source-keys-v1`。

自动回归用不含项目角色数据的 GLTF 合成补偿动作，在 0.017、1.7、170 三种尺度下实际运行 Godot 导入。默认策略复现小模型脚部滑动，新策略保留髋部运动及脚部接触点。测试还检查插件配置重复安装及其他插件保留。实际陈伯 FBX 的新策略复测结果：左脚屏幕水平跨度 0.232px，右脚 0.054px；默认分别为 7.078px、7.233px。

修改仅作用于新建的处理项目。已发布图集、已打开的旧预览项目和游戏中已经打包的旧版本不会自动改变；需要从原始动作重新烘焙，再选择新的交付版本。原始模型、动作文件与历史交付保持不变。新交付的动作审阅状态也不沿用旧图集的人工确认。
