# Pixel Animation Studio：项目与功能总览

更新：2026-11-04。本页说明现有功能如何服务素材制作；定位与总流程以 [Studio 定位与素材制作总流程](production-workflow.md) 为准。具体项目界面规则见 [素材项目组织](studio-projects.md)。此次整理只修改文档，没有重新测试全部工作台，也不表示完成软件改造。

## 项目定位与制作顺序

Studio 帮助制作者把游戏素材需求，经过生成、导入、调整和组合检查，变成可以接入游戏的素材。

制作顺序：**明确使用目标 → 拆解素材套件 → 建立共同基准 → 做代表性组合 → 扩充整套素材 → 接入与反馈。**

这是一种制作方法，当前界面没有六阶段工作流或强制审核。项目首页仍展示需求与当前素材，各工作台负责制作和下载，验证工具按需使用。历史与视觉判断依靠制作者、参考资料和实际候选；Studio 负责组织制作条件、管理结果及提供处理与接入能力。

素材套件是可重新组合的成果，Demo 是它的一次使用。地图面积、重复实例数量和玩法数量不能代替套件丰富度或使用效果。

## 现有功能在流程中的位置

| 制作环节 | 当前可用入口或能力 | 仍需制作者完成的工作 |
| --- | --- | --- |
| 使用目标与清单 | 素材项目、共同风格和规格、需求描述、批量导入清单 | 确定题材、用途、空间组成及各类素材的关系；当前没有独立的关系规划工具 |
| 共同基准与单项制作 | 各类工作台、描述与参考输入、生成或导入、单项预览 | 选择基准素材，检查真实输出是否符合要求；各工作台的输入能力有差异 |
| 代表性组合 | 项目组合预览、模块场景、Godot 验证工程 | 选择有代表性的小空间，比较比例和搭配，复现连接与通行问题 |
| 扩充素材套件 | 项目需求清单、已有素材选择、单项再制作与调整 | 分批补齐类别、方向和变化，检查新结果；当前没有通用整套自动生产队列 |
| 接入与反馈 | 素材下载、人物动作包、模块场景导出、专项检查和 Demo | 检查实际画面和操作，定位问题，修正素材或接入；已检查范围需明确 |

项目组合中的显示比例仅用于比较；素材编辑器中的实际尺寸用于接入。模块场景固定引用具体素材版本，修改素材后需显式更新相关引用。两者的详细规则见对应操作文档。

## 各类素材能力


“已实现”表示存在实现路径，不表示所有素材均已通过美术验收，也不表示已经达到正式生产就绪状态。

| 素材类别 | 现有生产能力 | 主要成果 | 当前限制或待验收项 |
| --- | --- | --- | --- |
| 人物与动作 | 原画重建或外部 GLB 导入、模型准备与减面、Mixamo 辅助绑定和动作下载、Godot/Blender 渲染、时序精简、共享调色板、动作集生产 | 图集、逐帧时序、预览、动作集、Godot 人物包及使用契约 | 绑定仍有人工作业；动作语义、朝向、循环接缝、轮廓稳定性和风格适配需要复核 |
| 武器与装备 | 独立武器输入与重建、握持标注、持用/收纳配置、随人物动作渲染 | 装备配置及带装备的人物成果 | 属于人物生产的配套能力；依赖绑定与动作，不能视为完整装备玩法系统 |
| 独立地表 | AI 材质或图片导入、平铺处理、变化组、部分规格的等距投影 | 地面瓦片、图集、预览、清单和来源 | 重复感、纹理尺度和画面一致性仍需目视检查 |
| 地表过渡 | 复用两份地表，按共享角点生成 16 种组合与变化组；已有等距投影实现 | 过渡瓦片、图集、角点规则及来源包 | 不是通用地形编辑器；场景绘制、变化组自动分配等能力尚不完整 |
| 道路 | 地面与道路材质输入、固定宽度、四方向连接与自然边缘 | 道路连接块、透明道路层、图集及连接清单 | 当前支持正俯视道路；项目中的等距道路生产会拒绝 |
| 静态水体 | 独立水面、陆地与水面的湿岸/浅水过渡、水域覆盖遮罩 | 水面与水岸素材包；部分新过渡包带保守阻挡代理 | 不含动态水面、深度或流场；不能假定所有历史水岸包都有碰撞 |
| 独立物件 | 石头、木箱、灌木、自定义物件的 AI 生成或导入、透明处理、裁切、规格化和重新后处理 | 透明 PNG、预览、来源、锚点、基准比例、可选多块凸碰撞 | 单色背景处理不是语义分割；镂空/细叶等仍受限制；接触面和占地需人工判断 |
| 连接构件 | 木纹生成或导入、程序构造围栏模块、接口、建议碰撞及部分深度分层 | 12 模块围栏候选、图集、接口、组合样例和 ZIP | AI 目前提供木纹；完整四向墙门套件、可靠拼接与复杂遮挡尚未闭环 |
| 建筑 | 框线图定义形体，AI 生成外观、候选比较、透明处理、人工锚点/占地标注；可适配到公共物件版本 | 独栋建筑透明图、来源、标注与独立包 | 视角与结构仍需目视复核；单图长建筑的遮挡和多层空间未解决 |

## 共用能力与产品边界

| 能力 | 当前用途与边界 |
| --- | --- |
| 素材项目 | 组织共同要求、需求与当前结果；生成成功不等于视觉判断通过；项目没有采用、审核、整套发布或整套交付页面 |
| 素材编辑 | 静态素材可调整尺寸、锚点和多块凸碰撞；人物有独立的动作与时序数据；不同类别保留必要差异 |
| 图片服务与任务 | 配置服务、提交任务、显示错误、保留已有结果并按实际服务能力恢复；调用成功不保证内容正确 |
| 素材来源与复用 | 保存版本与来源、验证文件及导出包；复用条件服从当前制作任务，明代村落任务要求不引用旧场景素材 |
| 工作台预览 | 检查单项外观、透明边缘、动作或连接规则 |
| 组合预览 | 观察当前素材的比例、配色和搭配；不会修改原素材尺寸 |
| 模块场景 | 保存具体素材引用和布局，检查重复摆放、拼接、碰撞、排序与接入；不承担完整游戏制作 |
| Godot Demo | 使用素材并提供具体问题证据；通过一次路线或局部检查不代表所有素材和全部场景均已验收 |

## 当前整理方向

下一阶段先用现有能力完成代表性组合，记录可复现的制作阻碍。根据证据决定修正提示词、换候选、调整素材、修改布局或改进 Studio；不把所有产出问题都归为工具缺陷。

代码改动优先处理会阻断制作的具体问题，例如共同条件未正确传入、现有结果无法继续编辑、预览与导出不一致、文件数据丢失或错误恢复不清楚。更多类别、队列和摆放自动化，应由实际重复工作证明需求。

当前明代村落先暂停批量生成和地图扩建，保留已有成果作为代表性组合的候选和问题记录。具体下一轮制作方法见 [总流程](production-workflow.md#当前明代村落工作如何继续)。
