# 建筑素材生产流水线

主入口：`/buildings.html`。输入是**原始建筑框线图 + 建筑风格提示词**。
框线图定义形体、比例、门窗和视角；提示词只描述材质、配色和画风。
不要求用户先填写墙高、屋顶类型、楼层或门窗坐标，也不在生成请求中附加占地和碰撞参数。

## 主流程

1. 上传原始框线图、填写名称和风格提示词。可以先保存方案，不调用生图。
2. 明确点击生成，每次调用项目图片服务生成一张独立候选。
3. 不满意则使用相同框线图与风格再生成一张。全部候选保留，以整张画布相同比例并列展示，不按各建筑包围盒单独放大。
4. 选定满意的候选后，在实际图片上标记占地多边形和落地锚点，可选标记入口。设置成品画布宽度，整体等比例缩放。
5. 保存独立建筑素材包。修改标定后再次保存会创建新包，旧包不覆盖。

生成不保证严格遵守框线图，需要挑选。没有自动连续抽卡或自动付费重试。
框线图决定视角，程序不把任意透视图转换成等距图；选用前仍需判断是否适合项目。

## 自动处理与失败

系统保留生成原图及画布，对真实Alpha或可分离的品红/近白背景执行透明处理，检查边界和主要连通主体。
不根据预设墙体或屋顶轮廓裁切生成图，不宣称已经识别真实占地。

透明处理失败时保留原图，候选不能直接选用为透明素材。可以查看原图、继续生成，或免费重跑处理。
主流程不包含局部编辑、人工蒙版和透明修图。旧候选可继续选用，即使最新一次生成或透明处理失败。

远程任务已受理时只续查原ID，已有可信原图时只运行本地处理。
未提交的失败任务明确显示可能产生费用；提交结果不明时禁止重复提交，可补录服务商核实的原任务ID。
原图使用临时文件、带指纹回执和改名的保存协议，中断不会直接触发重新生图。

## 标定与交付

标定坐标以原始生成画布像素计量；透明图保留完整画布，不按包围盒裁切或重新居中。
成品按画布宽度统一缩放，锚点、占地与入口执行同一缩放，再导出相对锚点的占地坐标。
地格宽度64/128px仅用于标定时的比例比较和交付记录，不反向约束AI生成。
多边形必须有3–24个顶点、非零面积且不自交。占地是人工建议，碰撞默认关闭。
入口是可选的场景切换标记，不自动挖通碰撞。人物比例、真实物理和整栋单图遮挡仍需游戏内验证。

`studio.building-kit/0.2`包含：

- 成品透明图、深浅底预览、清单、ZIP和接入说明。
- 原始框线图、风格请求、生成原图、原尺寸透明图与预览。
- 实际提示词、输入图像用途及指纹、生成回执、自动检查报告。
- 人工候选选用记录、原图坐标下的标定记录、成品坐标下的接入数据。

`human_review=candidate_selected`只表示用户选用了候选，不表示所有建筑结构已经检查通过。
包保持`production_ready=false`、`game_integration=not_tested`。
选用和保存验证来源、生成回执和候选证据；文件变化或修订冲突会阻止保存。下载检查完整文件集合、指纹和ZIP一致性。

任务目录为`.local/buildings/jobs/<id>/`，产物为`building-kits/<id>/`，均不入Git。
文字方案与标定草稿保留在当前浏览器；框线图上传后点击保存方案才会持久保存。
改变框线图或风格时另存生成方案，保留原任务来源关系。

## 兼容与辅助工具

原参数化结构生成器保留在`/building-structure.html`，作为可选的结构参考/旧任务入口。
它仍只支持矩形、单层、双坡顶。旧任务从素材库或任务页打开时会进入此辅助流程。
原`studio.building-kit/0.1`包、生成记录、复核记录及API保持兼容，不自动迁移、重生图或改写旧包。
主流程不再要求六项结构复核，也没有“编辑所选候选”的生图操作。

`building_candidates.py`实现框线图方案、独立候选、标定及新包；
`building_pipeline.py`与`building_worker.py`复用持久尝试、生产锁、服务回执和安全恢复。
早期结构实验及审查记录见`building-production-study.md`与`building-flow-review-2026-11-02.md`。

## Google Cloud provider

框线图流程复用共用图片provider，可在`.env`设置`STUDIO_IMAGE_PROVIDER=google_cloud`，使用Vertex AI的`gemini-2.5-flash-image`。输入仍为原始框线图与同一份风格提示词，不加模型专有几何表单。同步返回图片归一化为现有持久候选，回执记录实际provider/模型，网络超时不自动重提。安装、凭据及切换方式见README。

## 建筑设置：线框模板

建筑页内的“建筑设置 · 线框模板”模块管理可复用母版，不另设顶层素材类别。
支持导入已有线框图，或通过当前图片provider生成线框候选。模板生成时只输入建筑形体描述及目标视角：

- `isometric_2_1`：项目推荐的2:1地格投影，地面轴线斜率±0.5。
- `isometric_true`：严格等轴测，地面轴线为±30°。
- `custom`：导入图片时沿用原图视角。

AI生成要求并不证明投影准确。用户检查平行线、垂直线、形体和留白并确认后，才能将候选保存为模板。
模板提示词用投影关系描述视角，不向模型提供角度数值供其标注，并明确排除文字、地格和内部辅助线。
外观提示词要求保留门窗位置、大小和用途，忽略参考图中的标注；背景保持纯洋红色，建筑自身可有明暗，
但不得向背景投影或受到洋红色环境染色。这些属于生成要求，仍需通过候选图人工检查。
建筑自动去底支持从四周采样均匀的粉红/洋红底色，并兼容带均匀内侧留白的一像素暗粉色画布边框；
只去除与画布边缘连通的底色，保持原始画布尺寸。不均匀背景仍会拒绝，投影不做语义消除。
模板候选不经过建筑外观的品红背景分离；它保留白底框线图，不能当成完成的建筑素材。
模板生成与外观生成共用一次一张、保留候选、显式再次提交和安全恢复机制。

模板保存到`building-templates/<id>/`，不入Git。每次保存建立不可变记录，包含名称、视角声明、
原图指纹、尺寸、来源和人工确认；AI来源另附提示词、生成回执与检查记录。模板不存外观风格。
建筑制作表单可选择已保存模板，也可继续本次上传。选模板不会改动风格提示词。
准备建筑任务时复制模板线框图和来源元数据，生成始终使用任务内快照；不实时依赖模板库文件。
保存建筑素材时包含`template-source.json`，可追溯母版来源。
