# 通用模块场景 MVP

入口：Studio 导航 → 验证工具 → 模块场景（`/module-scenes.html`）。用于验证素材成果。

2026-11-03 更新：当前库已支持建筑适配与人物动作集接入。人物以动作集结构可交付（`complete`）为条件，人工检查为可选记录；未检查与其他提示保留在快照和原始交付包中。本文下方各轮 MVP 的“尚未适配”等限制描述反映当时的实现范围。

## 工作流程

1. 新建场景，从“素材库”搜索并选用已保存的同视角物件版本。已有素材无需导出PNG再导入；新透明PNG（最大2048px）通过公共物件库导入后再引用，保留原始字节。
2. 双击素材缩略图或场景物件，打开独立标注窗口。可拖动绿色锚点、红色碰撞顶点，或拖出矩形碰撞；多边形逐点绘制后按Enter完成。可通过模块不带碰撞，门洞用多块区域留下间隙。保存模块设置后关闭窗口。
3. 从左侧缩略图拖入素材，或点选缩略图后在画布连续放置，画布显示放置预览。V返回选择、B切换放置、Esc退出放置。支持透明像素穿透点选、拖动、复制、删除、128×64地格吸附；选中物件后可编辑X/Y或用方向键微调（Shift为16px）。滚轮以鼠标位置为中心缩放，空格拖动/中键/右键平移，“适合画布”显示全部物件。
4. 设置出生点并保存布局。⌘/Ctrl+S保存，⌘/Ctrl+D复制，Delete删除，⌘/Ctrl+Z撤销，⌘/Ctrl+Shift+Z重做。重新打开可恢复模块、碰撞和全部实例；未保存的场景在切换前会保存。撤销重做用于当前页面的布局操作，不覆盖模块标注修改。
5. 下载 Godot 场景 ZIP，解压并用 Godot 4 打开 project.godot。WASD/方向键移动，C显示碰撞。测试角色半径8px。

## 数据与版本

2026-11-04：素材库增加已通过文件完整性检查的等距地表过渡与水岸套件。每套以一张卡片展示，先选变化组，再点击连接形状缩略图并加入场景；同套的不同形状可分别加入，重复选择相同形状与变化组会复用原模块。选用固定保存 `corners` 与 `variant`，预览图片来自对应原包瓦片。水岸块沿用素材包的通行与碰撞设置。该入口用于选用已有套件，不会自动根据邻格生成连接，也不代表图像美术检查通过。

场景保存在 `.local/module-scenes/<id>.json`，原图按SHA256存放在images目录。数据格式为 `studio.module-scene/1`。
所有操作检查场景revision，过期写入被拒绝。场景模块记录source.family/id/sha256，固定物件库的不可变版本。场景中的模块字段是该版本的接入缓存，读取时与素材包核对。共用的sprite-editor.js和/api/props/annotate用于物件工作台与场景标注，另存物件库版本后只更新当前场景的同模块引用。其他场景保持原版本；“替换引用版本”可显式换用新成果并保留实例ID和位置。旧场景本地PNG在首次标注时提升为公共物件素材版本。

坐标：屏幕像素、X向右、Y向下；锚点为图像像素；碰撞顶点相对锚点；实例只包含模块引用与位置。视角固定为2:1网格基准，导入图像的实际绘图角度由使用者确认。没有对PNG进行重投影。

交付包含scene.json、原始PNG、assets/内引用版本的完整素材包及通用Godot加载器；游戏侧不手工补实例位置或碰撞。碰撞区域建立StaticBody2D，角色使用CharacterBody2D。开口通行取决于实际间隙与角色半径，类型标签不保证角色一定可通过。单图素材按锚点Y排序；不保证长墙、复杂开口或跨深度物件的遮挡正确。

MVP暂不包含：AI成套生图、自动连接点、实例旋转缩放、导航、门扇开关、多层高度、复杂分层遮挡、建筑、地面和围栏套件的通用引用适配。当前库入口复用Studio独立物件库，其他类别尚未接入。程序几何样例只用于测试，不是正式美术。

旧墙段与门的连接接口没有校准为兼容套件，实际样例用于分别检查模块而非完整院落验收。门头及长墙的整图排序遮挡仍未解决。实际绘图投影与历史准确性不因通行检查通过而自动通过。

## 功能归属

- 素材生产、来源记录、锚点和多区域碰撞：公共物件工作台与不可变素材版本。场景中的编辑窗口是同一编辑器入口。
- 模块场景：素材版本引用、重复实例、布局、出生点与场景交付。
- 项目组合挑选：候选美术比较与采用，不作为场景布局；旧组合位置继续兼容，未迁移为场景实例。
- 导出：复用现有物件包的完整性校验及原始ZIP，场景只增加布局和加载器。

物件旧的宽深椭圆调整界面已收敛到统一多区域编辑器；旧remake接口保留生产兼容，但不能用其覆盖新的多区域标注。透明背景重处理仍是独立生产操作。

## 场景基准尺寸

共用素材编辑器提供等比联动的宽、高和恢复原图尺寸，尺寸以完整透明画布为准，单位是屏幕场景单位。素材版本保存 `world_scale`（0.01–100，旧版本默认1），原始PNG不重采样。标注编辑仍使用原图像素；场景预览和Godot加载器对图片尺寸、锚点偏移、相对锚点的碰撞顶点统一乘以该比例，实例位置不缩放。地格基准128×64，镜头缩放只影响观察。

尺寸设置属于素材库，不新增实例缩放或Z轴；修改另存不可变版本，当前场景更新引用，其他场景保留旧版本。透明边距可能影响宽高读数，应结合锚点、碰撞和场景中地格判断实际占地。

### 尺寸交互

素材编辑默认进入“场景大小”：通过比例滑块或百分比即时比较素材与128×64地格、34单位高的测试角色；宽高输入仍保持等比联动。预览镜头在调整过程中保持固定，“适合预览”用于重新取景；重置恢复100%。切换“锚点与碰撞”进入原图像素标注，两种视图共用同一份设置。底部固定显示保存状态和保存按钮，非法尺寸会阻止保存。

2026-11-04：共用素材编辑器新增“主体宽 / 主体高”，按当前原图非透明像素的包围范围显示场景尺寸，可直接输入目标值。修改仍使用同一份等比缩放，画布宽高、比例与主体尺寸联动；不裁图、不重采样，不新增导出字段。原图锚点和碰撞坐标保持原值，在场景中统一乘以该比例。完全透明的图片禁用主体尺寸输入，仍可使用画布尺寸。阴影、碎屑等非透明像素也会计入，因此主体尺寸不等于自动识别的物理高度或占地。

同日进一步统一为“标准人高 = 1”：主体宽高默认使用人高单位，例如水缸主体高输入 0.6，表示标准人高的 60%。编辑器黄色参照、模块场景出生点人物与新导出 Godot 测试角色使用相同基准。原图比例和含边距的画布尺寸收进折叠区；锚点与碰撞标注仍使用原图像素。

内部兼容换算为 1 人高 = 34 个既有场景坐标单位；原始文件和 `world_scale` 含义保持不变，不自动改写旧版本的大小。项目的“人物制作分辨率（px / 标准人高）”控制制作清晰度，不改变标准人物在场景中的高度。该比例基准不指定真实米数，也不自动把任意人物动作包归一化：正式人物仍需按其实际主体高度设置接入比例。已经导出的工程需要重新导出才能获得新的参照标注。

## 双入口小院拼装验收（2026-11-03）

Studio 场景 `a290ac9db8e10047`，标题“宋村 · 双入口小院拼装验收”。复用已有院墙、院门、井和菜畦原图，通过公共素材标注和场景操作创建4个版本、11个实例（6墙、2门、1井、2菜畦）。现有 `19aaa6dc899b5b27` 场景保留用户修改。墙/门比例0.65、井0.28、菜畦0.4，以通用测试角色高34单位、半径8单位作参照；这些是此样例的校准值，并非全库尺寸标准。

```sh
.local/python/bin/python3 pipeline/validate_courtyard.py
# 复验已交付场景，无需创建新场景：
.local/python/bin/python3 pipeline/validate_courtyard.py --output .local/courtyard-acceptance/a290ac9db8e10047
```

该命令调用Studio共用的素材版本、场景保存及导出函数；布局由脚本根据人工标注端点计算，不代表已验收人工拖放操作效率。导出游戏不补碰撞、不镜像、不修图、不改实例位置。PNG逐一核对原始SHA256。Godot检查24项墙段/接缝/转角/门洞/井/菜畦碰撞探针、真实键盘移动、从前门进入绕井后穿后门的连续路线，并核对所有实例、图片比例、锚点偏移和碰撞坐标。报告及交付位于`.local/courtyard-acceptance/<scene>/`。

验收发现：

- 两张历史“左下/右下”墙图实际上都朝同一方向，因此用前后两座门闭合短边，尚无完整四向墙套件。
- 墙段有明显立柱/瓦檐接缝，墙门高度和斜率也不一致。物理探针通过不等于画面无缝，视觉拼装验收未通过。
- 当前网格吸附不表达素材连接端点；布局需人工测量并算坐标。建议下一项MVP为通用素材连接点定义及放置吸附，先用墙门验证，不引入院落专属规则。
- 整图脚底排序仍存在长墙/门头遮挡限制，尚未通过复杂遮挡验收。
- 行走仍使用通用黄色验收角色，未适配历史人物动画素材；连续路线为指定路点的实际物理移动，不是导航寻路。

## 小院地面接入

小院 `a290ac9db8e10047` 已加入此前生成的“春日草地”和“村路夯土”，共50格（42草地、8夯土），原有11个物件实例和出生点保持不变。脚本 `pipeline/add_courtyard_ground.py` 可重复应用布局，首次运行前保存 `before-ground.json`。

直接引用 `source.family=terrain` 与原始地面ZIP指纹，复用terrain_integrity验证。采用交付包首个2:1投影瓦片、128×64地格和中心锚点；PNG字节不变，不复制生产为物件。地面固定 `layer=ground`，无碰撞；物件默认objects。Studio按层再按Y绘制，Godot地面固定在物件下方。该层是绘制类别，不是实例高度。

素材库可选用等距地面，在场景中重复放置、替换引用；固定地格设置只读，调整回到地面工作台。当前没有地形画刷、区域填充、变化块分配和草土过渡。地面原始ZIP保留在交付assets目录。铺地后24项物理探针、连续路线和导出变换/地面层核对通过。

## 场景与素材平铺展示

模块场景首页用带素材缩略图的卡片平铺展示已有验证场景，点击卡片进入，当前场景以边框标识。卡片显示名称、素材数量及摆放数量，不再使用场景下拉框。切换场景前保存已修改的布局；未保存的素材设置仍需先处理。

场景内素材以图片网格展示，可直接点击后在画布放置，也可拖入画布；键盘可聚焦卡片并用 Enter 选择。手机端场景卡片两列、素材卡片三列，画布单独占一行。素材库继续使用可搜索的图片卡片。
