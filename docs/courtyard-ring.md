# 四合院院墙：扩建验证

项目 `20261103-213712-24c6e327`（四合院 · 院墙重建）。验证目标是同一套转角与直墙增加重复数量后仍闭合，而非将整张图原样还原。旧固定尺寸场景 `7ace5b4451c78635` 只验证了切图，不能作为扩建通过依据。

## 制作与布局

Studio 从完整院墙 AI 来源中，通过 `courtyard_expand.py` 同时比较两面相对墙，分别搜索 A/B 两方向的共同重复间距和切割路径。偶数间距搜索范围 32–160；三像素边界采样，四面墙分别检查瓦顶差不超过18、墙面差不超过10、轮廓不超过1px、透明差不超过1.5%。取两面相对墙各项最差值，不平均掩盖某面失败。不通过就拒绝发布。

在投影地面坐标中，两组路径将来源分成四角及四面重复墙。四角保持原像素，所有布局始终各放一次；A/B 墙按同一个对应方向间距重复。右、左、前角位移由重复数直接计算，前角位移等于两个方向之和，不手调最后一个接缝。切割仅选择来源像素，无重绘、缩放、混合或逐实例修补。每件保留完整来源画布及地面锚点，纹理本身不缩放。

生产默认 `courtyard_ring.build_job` 已切换为扩建配方。历史 `build_fixed_job` 只用于回归。项目“生成”及物件工作台共用 `static_props.prepare/execute`，生产前自动验证基准、单轴及双轴扩建五种布局。校验全部来源像素可还原、四角各一次、院墙闭合、无像素重叠且没有新增内部透明孔。它只验证这些离散尺寸及边界测量，不保证任意图片均成功、任意连续尺寸、院门、物理、遮挡或其他造型。

## 手动组装与自动布局一致

扩建素材的重复位移为 `(40,20)` / `(-36,18)`，不属于默认128×64网格。此前只写入了自动布局坐标，没有将切口接口接入模块场景，因此手动吸附会落到错误的网格点；原样演示不能证明手动工具可用。

`connection_ports` 现从每件素材的已校验切割参数推导来源坐标接口，相减后得到锚点局部坐标。接口按来源指纹、方向及墙面分组，只有同组的起止接口可吸附。转角包含两面墙的接口，直墙包含对应墙面的起止接口；两接口差就是其重复位移。“复制”使用这个位移，而非固定向右128px。关闭吸附仍是自由摆放。旧素材无需重生成：读取已校验包内的 `expansion-checks.json` 即可派生接口，旧场景加载时补充内存接口，不移动现有实例，不修改不可变素材包。

`test_courtyard_manual_browser.py` 通过真实鼠标点击摆放两方向的首段墙、复制后续墙、放置远端转角并保存刷新，逐个核对其坐标等于自动扩建规则。仍需用对应的前/后墙素材；外观相似的不同墙面或其他来源不保证可以交换。

## 开放院门与实际通行

Studio 项目院墙详情增加“构建院门与通行场景”，调用 `/api/projects/courtyard-access`。它复用当前已完成的扩建任务，不调用生图服务，不修改原素材或旧场景。`courtyard_access.py` 从左前墙重复5段构成替换模块，在实际墙脚范围中部减去92px宽、100px高的门洞，保留原瓦顶；接口末端按5段总长度推导，可继续接相同墙面。当前仅做无门扇、无装饰门框的覆盖式开放通道，不能称为完成美术院门。

墙脚从同源墙体下边缘拟合，碰撞只保留贴近实际墙脚的窄凸带；不能把被切割的上部断边当作脚底，否则门洞会被相邻切片的空中碰撞阻挡。门洞净空不生成碰撞。长斜墙通过 `occlusion_slices` 将图像分成4px宽的原尺寸竖条，各条按当地墙脚Y排序；门洞上方仍使用原墙脚，而非横梁底边。导出Godot场景读取相同元数据。浏览器场景编辑器仍用于摆放和碰撞预览，人物实际通行与遮挡在Godot中验证。

当前素材 `20261103-221329-a2d847eb`，场景 `36e225584d6607ea`，使用9×7扩建院墙，门洞替换左前墙最初5段。新碰撞墙版本与旧PNG像素一致。项目另列“带瓦顶开放院门”作为可复用素材。构建记录存于原扩建任务 `access-build.json`，重建复用已生成场景，不覆盖布局。当前构建参数仅验证至少5个A向重复的院落；换方向、不同开口位置与多门仍未实现。

可重跑：`.local/python/bin/python3 pipeline/courtyard_access.py .local/props/jobs/20261103-214834-10191c9f --validate --visible`。真实Godot4.6.2测试12个探针：门洞双向通行，两侧阻挡，以及四角四边各一个代表区域的阻挡。半径8px测试角色使用实际 CharacterBody2D 碰撞运动；不代表所有人物尺寸或全部墙缝均已验收。可见渲染另核对3个采样点：墙后角色被遮挡、墙前角色可见、门洞内角色可见。测试画面与 `access-physics.json` 留在任务目录，输出通过。WASD/方向键移动、C查看碰撞。

`test_courtyard_access.py` 验证上部残片不会误作地面碰撞、门洞无阻挡、横梁仍按地面排序，以及计算过程不更改输入像素。原有 `validate_module_scene.py` 的Godot导出回归通过。尚未提供真实人物动画接入、开关门、导航或多层高度。
