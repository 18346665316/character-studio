# Studio 定位与素材制作总流程

更新：2026-11-04。本文记录本次讨论确定的产品方向和制作方法。它不表示软件已经实现全部流程，也不要求新增审批、验收或发布页面。具体界面操作以 [素材项目组织](studio-projects.md) 为准，功能对应关系见 [项目与功能总览](product-map.md)。

## 产品定位

Studio 帮助制作者把游戏素材需求，经过生成、导入、调整和组合检查，变成可以接入游戏的素材。

主要成果是一套可以重新组合和使用的素材，包括图片、动画，以及使用这些素材需要的尺寸、锚点、连接或碰撞数据。Demo 是这套素材的一次具体使用，用于发现问题和提供接入样例。

项目进展优先看：制作能否顺利完成，结果是否符合用途，修改是否方便，组合是否成立，导出后是否能实际使用。素材生成数量、重复摆放数量、地图面积和玩法数量只能说明各自的规模，不能单独说明素材套件已经完成。

## 职责分工

| 参与者 | 负责什么 | 如何判断结果 |
| --- | --- | --- |
| 制作者 | 使用目标、题材与地域、参考资料、清单、提示词、候选选择和视觉判断 | 查看结果，对照用途与参考，决定保留、调整或重新制作 |
| Studio | 组织需求和共同制作条件，调用生成服务或导入素材，保存结果，提供调整、复用、组合检查和导出 | 检查可确定的数据与文件条件，并清楚显示当前结果、失败原因和可继续的操作 |
| 图片模型与外部工具 | 按输入制作候选图片、模型或动作 | 由制作者查看实际产出；请求成功不代表内容正确 |
| Godot 与验证场景 | 消费素材，暴露比例、拼接、碰撞、遮挡、动画及接入问题 | 结合实际画面、操作和针对具体问题的测试判断 |

历史准确性通过参考资料、描述、提示词和人工判断逐步改善。Studio 可以保存、传递这些制作要求，但不承担自动历史考证。视角和风格要求写进提示词，也不等于结果已符合要求。

## 总流程

**明确使用目标 → 拆解素材套件 → 建立共同基准 → 做代表性组合 → 扩充整套素材 → 接入与反馈。**

这是一种制作顺序。单项下载和验证工具仍可随时使用，不增加强制采用、审核或整套发布步骤。发现问题后回到相关环节，不必重新走完整套流程。

| 阶段 | 主要工作 | 应留下什么 | 下一步的判断依据 |
| --- | --- | --- | --- |
| 明确使用目标 | 确定游戏用途、显示视角、典型镜头、人物与地格尺度、需要的使用行为 | 简短制作说明，必要的参考图片或资料 | 能说明素材在哪里出现、以多大尺寸显示、需要怎样使用 |
| 拆解素材套件 | 按空间和用途列出素材，区分独立物件、重复块、连接构件、动画及变化版本 | 带用途和关联说明的清单 | 能分清需要不同种类，还是同一素材的重复实例；连接需求有明确对象 |
| 建立共同基准 | 明确配色、材质、光照、视角与尺寸；制作少量关键候选 | 共同描述、参考和基准素材 | 有可供后续对照的实际成果，不只是一段风格文字 |
| 做代表性组合 | 把关键素材放在一起，检查画面与实际使用；调整候选、尺寸、锚点、碰撞等 | 小型组合或验证场景，具体问题与修订结果 | 在目标镜头下，比例、搭配及必要的连接或通行方式基本成立 |
| 扩充整套素材 | 沿用已成立的基准，分批补齐类别、方向、连接块与变化；边制作边检查 | 可重新组合的素材套件 | 每项满足实际用途，新增素材与基准相容，关键类别缺项清楚可见 |
| 接入与反馈 | 在目标引擎中使用素材，逐步扩大场景并检查实际问题 | 引擎样例、修订素材、使用说明和未解决项 | 结果按具体版本和使用范围说明；有问题能定位并回到制作处修正 |

代表性组合的内容取决于任务。村落可以先用一段道路、一处民居、少量生活物件、植被和一个角色尺度参照形成可阅读的小空间；若目标包含院墙或桥，应分别尽早验证墙门连接或桥面通行，避免在大场景阶段才发现使用方式尚未成立。

## 按问题选择处理方式

| 实际问题 | 优先处理方式 | 何时考虑修改 Studio |
| --- | --- | --- |
| 时代、地域或建筑外观不合适 | 查参考，明确描述和提示词，检查新候选 | 共同要求无法保存或没有正确传入生产时 |
| 生成了错误主体、额外物件或复杂背景 | 检查输入与实际结果，修订描述或换候选 | 错误信息不清楚、有效结果被失败覆盖，或已有原图无法合理继续处理时 |
| 房屋、人物和器物大小不协调 | 在相同镜头下比较，用素材设置调整实际尺寸 | 当前编辑器无法表达尺寸，或预览与导出使用不同设置时 |
| 墙门拼不上、桥无法通行 | 明确连接方向、端点、可行走面和遮挡需要，制作专项小样 | 现有素材数据或验证工具无法表达实际所需关系时 |
| 村落稀疏、内容单一 | 重新检查清单、空间安排、类别与变化，不只增加复制数量 | 已明确的摆放工作被重复操作严重拖慢时 |
| 在引擎里出现碰撞、排序或动画问题 | 用具体素材和位置复现，修正素材数据或接入代码 | 证据说明导出丢失数据、设置含义不一致，或现有表达确实不足时 |

模型偶然生成错误、一次服务失败或一次布局不合理，都不能单独证明 Studio 缺少某项功能。记录问题时至少说明：输入和素材版本、实际结果、期望用途、已尝试的处理方式，以及剩余阻碍。

## 当前明代村落工作如何继续

现有明代项目和 Demo 保留为制作记录与问题样例。已生成的本项目素材可以继续检查和调整；用户要求不复用旧场景素材仍然有效。当前暂停新的素材批量生成和 Demo 扩建。

下一轮先写清本项目的使用目标，并从现有新素材中挑选一组代表性组合，集中解决视角、尺度、画面搭配和最基本的通行问题。选择不适合的候选时，修订描述后重新制作。组合成立后，再分批补齐村落清单并扩大场景。

本项目的具体使用假设、候选、尺度起点和首个组合安排见 [明代村落制作说明与代表性组合](ming-village-brief.md)。其中的建议参数尚未写入软件或作为正式规格使用。

人物若尚未制作，可用明确标注的尺度参照辅助检查；它不能代替正式人物与环境搭配的结论。桥、院墙等尚未完成的使用方式单独验证，不以已经有图片或已经能导出代替接入成功。

## 下一阶段的产品工作

先沿上述流程实际完成一个代表性组合，记录具体操作与阻碍，再决定需要哪些界面或代码改动。优先修正当前流程中的信息缺失、设置不一致、结果无法继续编辑或导出不正确等可复现问题。

后续功能建议应说明它服务哪个制作环节、解决哪个已出现的阻碍、现有方式为何不足，以及怎样确认改进有效。现阶段不因“成套素材”这个目标直接新增项目发布、人工审批、历史准确性评分或大型地图系统。
