# 素材空间语义与碰撞交付规范

状态：围栏生产的首轮约束；当前地表和水体未提供碰撞资源。不能把本规范理解为现有素材已经经过物理验收。

围栏几何原型已实现：执行 `pipeline/fence_components.py` 生成标记为非正式美术的12模块包，再执行 `pipeline/validate_fence_godot.py --kit <ID>` 独立验证真实物理。当前已在Godot 4.6.2通过95项检查（默认圆形角色半径4px，另有半径14px门洞反例）。模块包中的 `engine_physics` 保持pending，不修改已发布包；外部验收报告记录本次结果及来源ZIP指纹。正式木围栏外观和角色遮挡仍为pending。

木围栏候选另提供地面深度层。在Godot用8×36像素测试标记通过28项加载与遮挡检查，验证横向前后排序和纵向近远层的独立排序。它不代表实际人物美术验收已通过，报告位于独立工程的 `qa/visual_report.json`。

## 分类约定

| 资产 | 默认物理交付 | 游戏负责 |
| --- | --- | --- |
| 普通地表、道路 | 不生成阻挡 | 材质速度、脚步声、可行走性 |
| 水面、水岸 | 当前仅有视觉覆盖遮罩，无碰撞区域 | 阻挡、游泳、减速、触发与导航 |
| 围栏、墙体 | 可选的落地阻挡形状与连接口 | 碰撞层、角色碰撞尺寸、门状态 |
| 独立石头 | 默认关闭的可编辑椭圆近似建议 | 确认落地范围、层与掩码、是否阻挡 |
| 建筑 | 后续提供占地、阻挡区及通行口 | 室内外切换、门、导航与玩法 |

覆盖率、深度、区域和碰撞是不同数据。水面灰度遮罩不可自动等同碰撞；未来若支持区域，应单独导出向量轮廓、简化误差和语义，经人工确认后由游戏选用。

## 围栏首轮交付

固定三分之四俯视、正交投影，不使用等距菱形网格。首轮使用64×64地面单元；图像允许向上超出地面单元，实际画布与偏移在清单记录。俯视纵向构件需要独立外观，不以横向图简单旋转冒充。

- `anchor_px`：图像左上角起算的落地点，单位像素，X向右、Y向下。
- `ground_origin_px`：图像中地面单元左上角。游戏把单元放到地图格子后，据此定位图片；透明留白不改变落地点。
- `connections`：地面平面中的接口位置、朝向和宽度。接口既约束外观接缝，也约束阻挡形状端面。
- `suggested_collision`：可选、可关闭的地面阻挡多边形；顶点以地面单元左上角为原点，像素为单位。与图像外轮廓独立。
- `passages`：门洞等通行区域与开口方向，不能被隐形阻挡形状覆盖。
- `occlusion`：落地线与排序锚点建议；角色在构件前后移动时需单独验收。
- `validation`：外观连接、几何连接、实际物理和美术分别记录；未执行的检查使用 pending，不能用几何检查替代美术验收。

视觉高度不参与地面碰撞范围。端头和转角的建议形状应在接口处连续；不以整张图片矩形、栏杆上沿或透明边界生成阻挡。

## 最小验证顺序

1. 先用明确标记的几何原型验证直段、转角、端头、接口和门洞。它不是AI美术成果。
2. 在Godot中实际测试从两侧接近被阻挡、沿边滑动、接缝不会穿过、门洞可以通过。
3. 再生成一种木围栏外观，绑定相同地面坐标和锚点。验证角色遮挡及外观与碰撞是否相符。
4. 外观与物理同时成立后再扩展T形、十字和门状态。

物理验收必须记录角色碰撞形状、尺寸和测试引擎版本。通过测试只证明该尺寸配置可用，不保证所有大小的角色或所有游戏玩法。

## 接入方式

图片和碰撞数据独立读取。Godot可将建议多边形转为可选的StaticBody2D/CollisionPolygon2D；导入器不得为普通地表或当前水体默认创建阻挡。门的开关、碰撞层与掩码、角色脚底碰撞体、导航数据由游戏决定。

## 独立石头素材

`studio.static-prop/0.1`的`anchor_px`位于输出图片坐标；放置精灵时使用`centered=false`、`offset=sprite_offset_px`（锚点的负值），节点位置表示游戏中的落脚点。画布尺寸不定义游戏世界比例。

`suggested_collision.polygon`使用相对落脚节点的局部像素坐标，不是图片坐标；默认`enabled_by_default=false`。该多边形来自可编辑椭圆近似，不是Alpha轮廓或真实接触面识别。游戏可完全不创建碰撞，自行指定层、掩码和阻挡规则。调整锚点不会移动精灵像素；接入时精灵偏移与碰撞应一同使用新清单。当前没有实际引擎物理或角色遮挡已通过的声明。
