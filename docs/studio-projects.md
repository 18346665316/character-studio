# Studio 素材项目组织

首页和导航改为素材项目、生产、组合挑选、交付。原全局素材库、制作分类和任务页不再是主导航。
既有工作台保持生产职责，新增的项目数据负责清单、共同基准、选用与整套交付。
这不是地图编辑器：组合页仅检查视觉搭配，游戏规则、物理、导航和室内行为仍由游戏实现。

## 操作流程

1. 建立项目，设置共同风格、配色、光照、视角、地格宽度与参考人物高度。
2. 加入具体需求。从每项需求进入对应工作台生产，或通过该项的已有成果选择器选用。
3. 项目内展示选用结果及关联生产任务，可编辑、归档和恢复需求。替换选用不改写原素材。
4. 组合页以首个地面铺底，其他素材按锚点摆放；可拖动位置、调整显示比例。
5. 在组合中比较、替换并采用结果，位置和备注可选保存。采用齐全部清单后即可导出，无审核勾选门槛。

人物选用要求已有可交付动作集，取首个动作的第一帧作组合对照；不会把人物工作区冒充完成的素材。
地面取独立单块，等距地面使用程序导出的菱形单块；道路、水岸、围栏暂用套件预览，不能据此验收全部拼接或遮挡。
显示比例只保存在项目组合中，不改写原素材包。消费项目交付时需要读取项目中的位置、比例与各包接入说明。

## 批量录入清单

生产页“素材清单”内点击“批量导入清单”，粘贴内容或选择JSON文件，先预览再导入。
格式为 `{"items":[{"kind":"prop","title":"木箱","description":"单个关闭的农用木箱"}]}`，也接受直接的数组。
kind使用界面列出的类型标识；title最多60字，description最多2000字，一次1–200项，项目上限200项。
同类型同名条目会跳过，不覆盖原描述、选用成果或共同基准。整批校验通过后一次写入；导入不启动生产任务。
可复用的春季农场清单见 `docs/prompts/stardew-inspired-spring.json`，含24项当前工作台可承接的需求。

## 共同基准与任务

清单项有“生成 / 再生成”入口：地面、道路、水面、围栏与物件在共同风格、需求和图片服务就绪后可直接启动一次生产。
服务端重新校验项目版本、视角与完整输入，并沿用原任务锁和任务记录；不自动重试、不自动选用。
物件默认自定义类型、256px、无碰撞；道路默认50%宽度、自然边缘。其他设置可从工作台调整。
建筑可在清单中选择并保存线稿模板绑定，模板视角需匹配项目（或人工确认的原图视角），绑定后支持一键生成外观。建筑设置支持正面斜俯视模板生成及导入。过渡及水岸需先选择来源，人物需先准备模型动作；对应项显示原因并保留工作台入口。
当前没有整套自动排队生成；一次只运行一个生产任务，完成后刷新进度。

工作台链接带project/item上下文。建筑新方案使用项目风格；AI材质、物件和围栏描述附加共同风格。
导入来源不附加生图要求。物件AI视角、独立地面投影和地格尺寸沿用支持范围内的项目规格。
人物的既有模型、动作和渲染不会自动变更画风；共同基准作为参考，仍需检查输出。
等距道路目前不能生成，正俯视物件AI目前不能生成，会明确拒绝；导入和选用仍需人工核对适配性。

任务关联保存请求时的基准快照和描述摘要，旧任务继续执行原输入。刷新后的工作台才能使用新版基准。
项目记录在`.local/studio/projects/<id>/project.json`，任务上下文另存`.local/studio/task-context/`，
不修改旧任务schema或已发布交付。直接访问旧链接仍可操作历史素材，但不会自动猜测其项目归属。

## 不可变选用与交付

选用时调用原类别的完整性验证，再把ZIP与对照图保存到项目selected目录，关联SHA256。
来源发生变化或被移除后，选用快照和已交付版本仍可保留。快照损坏会阻止组合保存和导出。
共同基准、需求和选用变化会清除旧组合位置记录；历史交付ZIP保持不变。
所有修改检查项目revision；旧页面或旧基准的请求被拒绝。

交付内每项素材保存独立ZIP，project.json记录名称、类别、选用指纹、基准、任务、比例与组合挑选。
人工采用只表示版本选择，不代表引擎接入或生产就绪，交付明确保留production_ready=false。
项目数据、选用快照和交付均不入Git；旧素材目录保持兼容。

## 验证

`pipeline.tests.test_studio_projects`覆盖版本冲突、快照损坏、跨类别拒绝、任务基准继承、归档恢复、
来源变化后交付稳定，以及浏览器从选择素材到组合挑选、交付、工作台上下文的完整流程。
真实素材的桌面和390px界面检查在临时项目中进行，不创建用户项目、不调用生图。

## Google请求节奏与透明恢复

Google图片请求之间至少间隔30秒，跨工作进程保存。遇到429后，根据Retry-After秒数等待60–900秒（未提供时60秒），约束后续请求；失败的请求不会自动重发。冷却只能减少请求过快导致的限流，无法解决账号配额耗尽或服务容量不足。
响应无图片时记录白名单内的finishReason用于诊断，不记录模型文本或敏感响应体。
AI物件先识别均匀的品红背景，再按其色域清理边缘污染及封闭区域残色，缩放后再检查并清理插值残色。主体不得使用粉色或品红材质，仍拒绝不均匀场景背景。导入模式保留原有规则，不清理内部颜色。额外删除超过主体区域20%，或缩放后仍有超过2%的可见品红污染时拒绝导出。处理记录包含清理数量，不等于语义分割或人工美术验收。显式继续已有物件任务时，若原图与回执匹配则只重新后处理，不重新生图。

AI物件成果页提供“重新处理透明背景（不生图）”，复用原图及生成回执，保存新的不可变版本；原图、旧交付包和项目已选用快照保留。用户检查新版本后可回项目清单替换选用。

## 相机与物件朝向

共同基准分别保存camera_rules（相机与画面轴线约定）和orientation_rules（物件默认朝向约定），网页可编辑。AI物件及建筑外观沿用这些约定，建筑模板工作台带入对应描述；地面纹理不附加物件朝向要求，继续按俯视平铺制作。字段属于请求说明，不构成自动投影认证。旧项目未填写时保持既有行为。

## 简化后的候选流程

成功导出的素材和建筑外观候选可直接放入“组合挑选”，无需先正式选用。项目任务中最新的可用成果会自动临时预览；临时预览不改写项目选用或交付快照。用户点击“采用此结果”才保存快照，可随时换其他结果。建筑候选直接采用时保存透明图与建议底部中心锚点，不提供占地或碰撞形状；主动打开“设置游戏占地与锚点（可选）”才能手动标定。

保存模板不再要求确认视角，保存仅表示复用。文件与回执哈希校验、请求版本检查和损坏拦截保留。组合位置保存不再要求逐项勾选，也允许只保存已采用的部分；整套交付仍要求所有有效清单项均有采用成果，但不要求额外人工验收。review字段兼容历史记录，新保存scope为composition_layout_only，不再表示美术审核通过。

## 页面组织

项目页用已采用素材拼图展示项目，新建表单默认收起。生产页为素材预览网格，名称只在展示时去除导入清单附带的类型注释，原需求名称保留。点击图片挑选候选；详情弹窗编辑需求与建筑模板，来源、生产记录和归档操作按需查看。

候选选择器默认只列当前需求关联任务的成果及已采用版本，另有“素材库”入口选用同类型其他素材。切换需求时重置搜索。进入工作台优先打开已采用成果的来源，或该需求最近任务；项目风格在紧凑上下文栏中展开查看。

组合页以画布为主、素材缩略图侧栏为辅，支持点选素材后拖动，点击空白不移动当前素材。显示比例与当前素材选择位于画布旁，备注和预览说明收起。交付页展示各项采用结果与缺项，保留最新交付下载，历史版本单独展开。
