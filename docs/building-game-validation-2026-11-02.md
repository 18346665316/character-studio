# 建筑游戏接入验证 · 2026-11-02

## 范围

将真实生成且已去底的建筑候选接入Godot 4.6.2独立场景
`demo/isometric/building.tscn`，复用既有草地纹理和96px人物。无新增生图调用，
不修改原候选，不生成正式建筑包，`production_ready=false`。

来源和测试估计坐标保存在本机忽略目录的`demo/isometric/assets/building.json`。
锚点为原图(526,636)，占地四点(266,694)、(396,781)、(786,579)、(656,492)，
入口(603,681)，整体缩放0.75。隐藏地面边界为估计，不能作为真实建筑结构。
此标定只适用于该候选；构建脚本拒绝对其他图套用相同坐标。

## 结果

Godot真实输入、物理和渲染共10项检查通过：人物移动、正面墙碰撞、向墙靠近、
入口范围内触发、范围外不触发、占地显示、地格显示、复位、后方被遮挡和前方可见。
物理测试等待physics_frame，图形测试比较有无人物时的实际画面像素。
图形检查只覆盖指定前后观察点，其他位置仍需人工检查。

画面已确认：

- 透明背景可融入草地，当前比例下96px人物与门的尺度大体可用于原型。
- 建筑与草地的纹理密度、人物与建筑画风仍未统一。
- 左侧可见落地边比2:1地格方向更陡；不能把模板视角声明当作严格投影验证。
- 侧后观察点(380,500)在估计占地外，但人物画在玻璃侧墙前。单一地面锚点的Y排序
  无法表达该建筑所有位置的遮挡关系。正面/后方两项测试通过不代表四周绕行遮挡正确。
- 入口标记可以响应交互；进入室内、开门和碰撞开口均未实现。
- 碰撞只验证正面一条路径，未声称全部墙边、凹角和路径规划已验证。

## 结论与下一步

素材可以用于固定视角场景原型；当前还不宜作为四周自由绕行且遮挡正确的正式建筑。
先确定游戏是否允许走到建筑背面。若允许，再选择适当的遮挡处理（拆分排序片段或
遮住人物时淡出）；若只作为外围不可绕行布景，可使用场景通行限制。
无需立即扩大生成表单，也不能靠反复生成保证解决整栋单图排序。
