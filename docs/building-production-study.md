# 建筑生产：结构先行的试验

先用一栋3×2格单层小屋验证共同的结构描述，再比较外观生产路径。
这是实验样本，不是所有建筑的尺寸限制，也不进入正式素材类型或制作界面。

## 两条路径共享同一结构

1. 确定墙体、屋顶、入口和地格比例，使用绘制或纹理制作外观。
2. 从同一结构输出参考图，交给支持图像编辑/参考输入的AI制作外观。

第二条路径只提供约束意图，不保证模型严格执行。需要比较轮廓、屋脊、
墙体转角、门口位置和比例；不符合时重新生成或修正，不用压扁、拉伸图片
冒充结构一致。第一轮不以通用“参考强度”滑块表示未经接口验证的能力。

## 结构样本

原始固定小屋试验保存在本地 `.local/building-reference/cottage/`。参数化编译器已替代固定脚本；运行
`.local/python/bin/python3 pipeline/build_building_reference.py --spec examples/buildings/cottage.json --output .local/building-reference/cottage-new`，输出至指定的新目录：

- `reference.png`：纯色背景、无尺寸文字、无网格的结构参考，可作为后续AI输入。
- `structure.png`：同坐标的透明结构图，便于轮廓叠加比较。
- `inspection.png`：占地、原点和入口的人工检查图，不用作美术生成输入。
- `structure.json`：地格基向量、固定像素比例、墙高、屋顶和入口记录。

地格采用现有128×64的2:1屏幕基向量；高度按每单位64px单独定义。
脚本不调用3D相机，不从现有相机元数据中的角度推导投影。
画布为该样本的留白范围，不执行“每栋建筑填满相同画布”的缩放。
屋檐超出3×2格占地；占地不是自动启用的碰撞体。

## 验证顺序

1. 先将结构样本放入等距场景，按实际游戏人物比例复核格宽、墙高、门高。
2. 检查绕行与门口接近，确定阻挡范围、交互区域及前后遮挡方案。
3. 选定美术风格，使用干净结构图约束生成；保存输入、输出和来源记录。
4. 在同一画布上比较轮廓及关键点，通过后再制作透明成品、碰撞建议和接入包。

首轮采用独立室内场景的入口设想，不实现原地揭顶或可拼装多层室内。
如果人物绕行出现整栋单原点排序问题，再按实际遮挡边界拆分前景与墙体。
尚未验证前，不承诺建筑能直接沿用石头/木箱的排序和占地估计。

## 后续制作界面的输入含义

- “用结构制作外观”：选择建筑结构和外观路径；AI路径再显示风格描述与可选风格图。
- “导入已有建筑图”：上传图、声明视角和地格比例，人工定位原点、占地、入口；不要求AI描述。
- “已有建筑换外观”：继承明确结构来源，修改风格；完成后依旧需要结构复核。

结构参考图和风格参考图必须区分；前者定义形体，后者只表达美术语言。
具体接口能否支持多图、输入角色或遮罩，需要接入时依据真实接口能力验证。
